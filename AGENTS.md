# VIK Playmaker

A mobile-first tool for the coaches of a youth football team (`vendelsoik-p10` on svenskalag.se). It syncs workouts and attendance from svenskalag.se and builds leveled training groups and teams from each player's level (A, B1, B2, C). It also keeps track of the lottery tickets the players are handed to sell for the team.

## Language

- All code is in English: identifiers, comments, database names, AI prompts, commit messages and docs. Page routes are the exception, as their folder names are the addresses users see.
- Everything users see is in Swedish: page addresses (without å, ä and ö), page text, buttons, form and error messages that reach the UI (including those thrown in `src/lib/`), page metadata, the login email and `<html lang>`.
- Data keeps its own language, such as svenskalag.se titles and the group names.
- Use the words coaches know from svenskalag.se and football: workout is "träning", coach is "ledare", team is "lag", league is "serie".

## Branding

The app is called VIK Playmaker, for Vendelsö IK. Colors come from the club's crest, blue `#0053a1` and yellow `#ffd100`, and are defined as theme tokens in `src/app/globals.css`. Use `bg-accent` with `text-on-accent`, as the accent is blue in light mode and yellow in dark mode. The crest is `src/assets/vik-crest.png`, with `src/app/icon.png` and `src/app/apple-icon.png` as icons. `src/proxy.ts` must keep letting the icons through without a login. The header bar shows the crest on the left, the page's title in the middle and a settings icon on the right, set in `src/components/page-title.tsx`, so a new page needs its title there, and the app's name appears only in the browser tab.

## Standing rules

- **svenskalag.se is read-only, except for närvaro.** The only allowed POSTs are the login and saving a workout's närvaro with `/{team}/controlpanel/presence/savepresence`, which replaces the whole present list, so always send the full list. Only `pushPresence` in `src/lib/svenskalag/presence.ts` saves it, and only where `SVENSKALAG_PRESENCE_PUSH` is `on`, which is production. Never set that locally, as dev and production share the same team on svenskalag.se. Never submit other forms or RSVPs, and never call `/schedules/invites/send`, `/{team}/invites/savereply` or `/{team}/invites/removeattendance/*`.
- **A save sends svenskalag.se's own member objects back untouched.** They hold names and birth dates, so keep them in memory only, like the pages they come from.
- **Never store or log raw svenskalag.se pages.** They contain parents' phone numbers. Keep the `workouts.raw` column unused for that reason. Don't read the "Spelare" section of the contact list, and don't use `/api/v1/{team}/schedules/{id}/invites/members`, which returns the whole club.
- **The AI only gets anonymous ids, never children's names.** `src/lib/grouping/claude-groups.ts` swaps player ids for throwaway aliases before each call. Coach notes are sent as written, so the Settings page must keep telling coaches not to use names in them.
- **Credentials live only in the gitignored `.env.local`** and in Vercel's env vars. Never commit them or put them in chat. The one exception is the svenskalag.se session cookie, which is kept encrypted in `app_settings` by `src/lib/svenskalag/session-store.ts`.
- **No Claude or Anthropic branding in the UI.** Those names are fine in code.
- **Mobile first.** Design for phones, with Tailwind v4.

## Stack

Next.js 16 (App Router, Cache Components), React 19, TypeScript, Tailwind CSS v4, Neon Postgres with Drizzle ORM, Anthropic SDK, Zod, and Resend for email. The dev server runs on port 8100.

## Routes

| Route | Purpose |
| --- | --- |
| `/` | Workouts: today's, upcoming and the last 14 days, each marked with how its närvaro stands against svenskalag.se (saved, waiting, failed, not saved, fetched from there, or none taken) |
| `/traningar/[id]` | One workout: its title from svenskalag.se, attendance, starting it and checking off who is there, leveled groups, teams, spreading new players |
| `/truppen` | A link to the lottery sales, the coaches with roles, emails and phone numbers, then active players and their levels |
| `/truppen/lotter` | Lottery sales (lotteriförsäljning), linked from the top of `/truppen`: the ongoing and finished ones with what has been collected and is left to settle, and a form for a new one |
| `/truppen/lotter/[id]` | One sale: totals, each player's tickets of each kind handed out and handed back, and the money they handed in |
| `/installningar` | Keep-apart pairs, free-text grouping notes and a button that runs the daily sync now |
| `/installningar/logging` | The audit log, newest first. Requires a login like every page, but nothing links to it |
| `/logga-in` | Email code login for coaches |
| `/api/cron/sync-svenskalag` | Daily sync at 14:00 UTC, protected by `CRON_SECRET` |
| `/api/realtime/workouts/[id]` | Renews an open workout page's live queries, for a logged-in coach |
| `/api/realtime/lotteries/[id]` | The same for an open lottery sale's page |

`src/proxy.ts` requires a logged-in coach for every page and Server Action, except `/api/cron/`. `next.config.ts` redirects the old English addresses to these.

## How it works

- **Sync** (`src/lib/svenskalag/`): logs in with a coach's own account and parses the pages, as there is no public API. The session is reused between runs, encrypted with a key derived from the login in the env vars, and when it has expired the client logs in once and reads the page again. It covers the last 14 days and the next 28, and a page that looks wrong fails the sync instead of overwriting data. Every activity in the calendar becomes a workout, whatever its title, such as a training, a camp or a meeting. Matches are the exception, as svenskalag.se keeps them on pages of their own under `/match/`, which the client doesn't read. It never changes a player's level or active flag. Coach emails, phone numbers and roles come from the "Ledare" section of the contact list, and only coaches' numbers are stored. Coaches are created from workout attendance and matched to the contact list by name. Only the daily sync clears the details of someone no longer listed, after attendance has refreshed the names. Deploys only add and update them, and a per-workout refresh fetches them when it finds a new coach. Workouts removed from svenskalag.se aren't deleted here yet. For a started workout the answers still follow svenskalag.se, but the check is only taken from there when svenskalag.se has one and none of ours is waiting to be saved, tested in the same statement as the write, and a row marked present is never deleted. Where saving is off the check follows svenskalag.se whenever it has one. The cron route and the "Synka nu" button on the Settings page both run `runDailySync`, so they do the same thing, and the button's run is in the audit log.
- **Attendance**: `player_response` is what the player answered, and `coach_check` is the coaches' own check, empty until registered. The check wins once it exists.
- **Live attendance** (`src/lib/attendance/`, `src/lib/svenskalag/presence.ts`): from 15 minutes before a workout a coach can start it, with no upper limit, so a forgotten workout can be filled in later. Pressing the button opens a dialog where the coach chooses whether those who said yes start as present or nobody does, and the choice is in the audit log. Starting first fetches the latest answers, then one statement sets `live_started_at` and marks whoever said yes as present and everyone else as absent, or everyone as absent, unless a check is already registered, such as one fetched from svenskalag.se, which is kept. The dialog is skipped when the page already has a check. With nobody present and nothing present on svenskalag.se, the first save finds the lists equal and sends nothing. From then every coach checks off players in the group and team cards. The Ledare and Spelare cards, which before the start list everyone's answer, then also hold a check for each coach and for everyone on the team, so a player without a group or one who was never asked is checked off there. Each tap is one statement that writes `coach_check` and bumps the workout's `presence_version`, and the other coaches' pages follow through the live updates. A toggle holds its tapped value until the page's data agrees, and the tap's action skips `revalidatePath` when live updates are on. Our database is the source of truth for a started workout.
- **Saving to svenskalag.se**: 5 seconds after the last tap, in `after()`, `pushPresence` saves the whole present list, and `presence_pushed_version` then equals `presence_version`. A lease column lets one save run at a time per workout, as the `neon-http` driver has no transactions or locks to hold, and that save loops until it has sent the newest version. It reads svenskalag.se's form first, skips the POST when the lists already match, keeps members who are neither players nor coaches, and fails if someone present isn't known to svenskalag.se. A list there that differs from `presence_pushed_ids`, the last one saved, was changed on svenskalag.se. Those changes are then written to our database first, guarded by `presence_version` in the same statement, and the list sent holds both sides' changes, so an edit made on svenskalag.se is kept even for a workout too old for the sync. Someone we changed since the last save keeps our value. Someone present there whom we don't have as a player or coach yet is left present. Only a first save, with no earlier list to compare against, replaces what svenskalag.se holds, and `presence_overwrote_at` records when. A failure is stored in `presence_push_error` and shown with a button to try again. A save that never ran is caught up by the next tap, by any open page after 20 seconds, and by the daily sync. Without `SVENSKALAG_PRESENCE_PUSH=on` nothing is sent and the page says so.
- **Groups and teams** (`src/lib/grouping/`): the AI proposes them, and pure functions in `level-groups.ts` and `teams.ts` validate the answer, with up to three attempts. Nobody moves more than one level from their home level. Teams in one league get each home level spread evenly, so no team has two more players of a level than another, which is retried like keep-apart pairs. Keep-apart pairs get the same retries, but the last answer is accepted if it only misses those. Groups are named after Greek or Norse gods, starting with the letter of the group's strongest level. Teams can be split by strength into two leagues from 4 teams and three from 6, with the stronger leagues taking any extra team. Teams in a league should have the same number of players, so when the players don't divide evenly only one league is left uneven, and none if whole leagues can take the bigger teams. Leagues follow the home levels, so nobody plays in a weaker league than someone with a weaker home level, though one level can be split across neighbouring leagues, and a league shouldn't hold both the strongest and the weakest level. These are retried like keep-apart pairs, and the order is left out when the teams keep the leveled groups. When a workout has leveled groups, a checkbox on the team form asks the AI to keep the teams as close to those groups as possible, which then comes before even strength between teams from different groups.
- **Persistence**: groups stay per workout and kind until a coach confirms creating new ones, and are shown blurred while the new ones are being made. A coach can also delete all groups or all teams of a workout, after confirming. Tapping a player in a group or team shows buttons to move them to another group or team, chosen in a dialog, or to remove them. These are the coaches' own decisions, so they skip the level and keep-apart rules, and a player removed while still attending is listed as a new player. Players who stop coming stay in their group and are marked, and new players are listed separately so they can be spread into the existing groups, or a coach can tap one to place them in a group or team chosen in a dialog.
- **Live updates** (`src/lib/realtime/`, `src/components/live-updates.tsx`): an open workout page subscribes through Neon Realtime to live queries on the workout, its player and coach attendance, its groups and their members, and re-renders on the server when any of them changes, such as when another coach moves a player or a sync runs. A lottery sale's page does the same with the sale, its kinds, players, tickets and payments. The queries select ids and states only, never names, as the browser receives the rows. Sealed queries are bearer capabilities that expire after a minute, so they are only made for a logged-in coach, first with the page and then through the renew route, which ends updates within a minute of losing access. A page that loses its connection keeps retrying, catches up when it comes back into view after a locked screen, and shows a floating notice that never moves the page, "Ansluter realtidssynk…" when connecting takes more than two seconds and "Försöker återansluta…" when a lost connection isn't back within five. Queries that have already expired when the page opens, such as from the router's cache, are renewed before subscribing. Without `NEON_REALTIME_URL` and `NEON_REALTIME_SECRET`, or if sealing fails, the page works as before without live updates. Realtime is enabled per branch in the Neon console.
- **Lotteries** (`src/app/truppen/lotter/`, `src/lib/lottery.ts`): a sale has a name, an optional last day and one or more kinds of tickets in `lottery_kinds`, each with its own price in whole kronor, an optional share of the price the team keeps and an optional number per player. Each player's row in `lottery_tickets` counts the tickets of one kind handed out and handed back (its `paid` column is no longer used). The coaches don't know which tickets a player sold, only the money handed in, so players settle on value: each payment in kronor goes in `lottery_payments`, and a player owes the value of their tickets not handed back, less their payments. The team's part of the money uses each player's kept tickets' share of their value, which is only an estimate, shown with "ca", when the kinds keep different shares of their price. The sale's page shows what has been collected, what the team has earned, what is left to settle and the tickets per kind, and lists every active player and anyone with tickets or payments. Coaches can take out a player who has neither and add anyone else, which `lottery_players` records per sale. The list has filters for those without tickets, those selling, who still owe money, and those redovisade, who don't. The button on the row of a player without tickets hands them every kind's usual number in one tap, and never adds to tickets another coach handed them meanwhile. Each row shows when the player was first handed tickets, from `handed_out_at`. Tapping a player opens a dialog with steppers per kind, the payments, each removable after confirming, a field for a new amount, and a button that undoes the hand-out after confirming, as long as nothing is paid or handed back. Its save writes the tickets in one statement that writes nothing unless every kind still has the counts the coach saw when opening it, so a change another coach made meanwhile is reported instead of overwritten, and then adds the new payment. A kind can't be removed once handed out. A finished sale is closed, which makes it read-only until reopened. The page follows the other coaches' changes through the same live updates as a workout page. Nothing is synced with svenskalag.se, and no parents' details are stored.
- **Audit log** (`src/lib/audit.ts`): every Server Action that changes something calls `recordAudit` after the change, and logins and logouts are recorded too, so a new action needs an entry and a Swedish label in `AUDIT_ACTIONS`. Only logged-in coaches are logged, so the daily sync and requests for a login code are not. A tap on someone's attendance is logged after its response, in `after()`, to keep the tap fast, and the saves to svenskalag.se that follow by themselves aren't logged. `details` is JSON where every id sits next to what it refers to, such as `{ "player": { "id": "…", "name": "…" } }`. A failed write is logged to the console and never reaches the coach, as the change has already been made. The daily sync removes entries older than 60 days.
- **Login** (`src/lib/auth/`): a 4-character code emailed through Resend, valid for 10 minutes. Three wrong tries use up the code, and every failed try gets the same message, so the form doesn't reveal who is a coach. A coach can get 5 codes per hour, and sessions last 90 days, but only while the coach has an email, so a coach removed from svenskalag.se loses access at the next daily sync. Only hashes of codes and session tokens are stored.

## Data model

## Code conventions

- Pages read data in async server components, inside `Suspense`, after `await connection()`.
- Mutations are Server Actions in an `actions.ts` next to the route, validated with Zod, used through `useActionState` and followed by `revalidatePath`.
- Server code that touches secrets imports `server-only`, and env vars go through `src/lib/env.ts`.
- Add new env vars to `.env.example` too.
- Only messages from a `UserError` (`src/lib/errors.ts`) are shown to coaches. Other errors are logged and replaced by a general Swedish message.

## Database and deployment

- Change `src/db/schema.ts`, then run `npm run db:generate`. Don't edit applied migrations.
- Production builds apply migrations and seed levels before the new code is live, so migrations must stay backward compatible.
- `DATABASE_URL` in `.env.local` points at the Neon dev branch `mattias`. `DATABASE_URL_PROD` is production, so ask before running anything against it.
